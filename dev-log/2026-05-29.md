- Important measurement correction: previous 7k runs captured via `./05_benchmark.sh -tps 7000 | grep P50` hide `ERROR:` and timeout lines. P50 rows are computed only from landed transactions, so grep-only output can look healthy while pending transactions and mined-timeout errors explode. The old “7k stable” conclusion needs rechecking with full output or at least `STATS|ERROR|P50`, not only `grep P50`.
- More precise bombard semantics from source:
  - P50/P75/P90/P95/P99 are calculated only from `latencySample`s appended by `markLanded`/`maybeFinalizeLocked`.
  - A tx that exceeds the hardcoded `5s` `timeoutSLA` is deleted from `pending` and increments `timeouts`.
  - If that tx lands later, watcher calls ignore it because it is no longer in `pending`.
  - Therefore `PERCENTILES (last N TXs, timeouts=M)` is a landed-only ring plus a separate timeout counter, not a distribution over `N + M` attempted txs.
